# Minecraft 1.12.2 — ванильный рескин клиента

В репозитории лежит `Impact-4.9.1-1.12.2.jar` и скрипт, который пересобирает его
в версию **без фирменного интерфейса**: главное меню, меню паузы, HUD и надпись
версии в F3 становятся обычными майнкрафтовскими, название клиента нигде не
показывается.

```
Impact-4.9.1-1.12.2.jar      исходный jar (не изменяется)
tools/vanilla_patch.py       патчер (чистый Python 3, без зависимостей)
tools/verify_jar.py          проверка результата
dist/1.12.2.jar              готовый вариант "ванильный UI, ClickGUI работает"
dist/1.12.2-full-vanilla.jar готовый вариант "весь интерфейс ванильный"
docs/icon-preview.png        новая иконка окна
```

## Что именно меняется в jar

| Что | Как |
|---|---|
| Главное меню клиента (`gui.MixinGuiMainMenu`) | миксин отключён → рисуется ванильный `GuiMainMenu` |
| Кнопка клиента в меню паузы (`gui.MixinGuiIngameMenu`) | отключён |
| `Impact 4.9.1` в F3 (`MixinGuiOverlayDebug`) | отключён |
| HUD: watermark, arraylist, оверлей чата (`gui.MixinGuiIngame`) | отключён → HUD нет, чат ванильный |
| `assets/.../credits.json`, `changelog.md`, `welcome.md` | вычищены |
| `icons/*.png` (иконка окна с логотипом) | заменены на нейтральную «травяную» |
| `log4j2.xml` внутри jar | пустая конфигурация, `Root level="off"` |
| даты всех записей в архиве | одна фиксированная дата (не видно, когда собран jar) |
| `META-INF/MANIFEST.MF` | оставлены только `Manifest-Version`, `MixinConfigs`, `TweakClass` |

Байткод, модули, конфиги, keybinds и сами миксины **не трогаются** — клиент
продолжает работать, просто перестаёт светить своим интерфейсом.

`dist/1.12.2-full-vanilla.jar` дополнительно отключает `gui.MixinGuiScreen`
(ClickGUI), `gui.MixinGuiChat`, `gui.MixinGuiChest` (peek в шалкер),
`gui.MixinGuiCustomizeSkin`, `gui.MixinGuiDisconnect`, `gui.MixinGuiGameOver` —
то есть вообще все кастомные экраны. Модули при этом остаются рабочими, но
открыть GUI клиента нельзя: управление только через бинды клавиш.

## Сборка

```bash
python3 tools/vanilla_patch.py Impact-4.9.1-1.12.2.jar dist/1.12.2.jar
python3 tools/vanilla_patch.py Impact-4.9.1-1.12.2.jar dist/1.12.2-full-vanilla.jar --strip-all-screens
```

Скрипт проверяет, что на входе действительно нужный jar (наличие
`mixins.impact.json` и `log4j2.xml`), и падает с кодом 2, если это не так.
Оригинальный jar не изменяется.

Проверка результата:

```bash
python3 tools/verify_jar.py Impact-4.9.1-1.12.2.jar dist/1.12.2.jar
# entries: 4241 | changed: 12
# mixins kept: 56 | username/branding mixins removed: []
# log4j Root level: ['off']
# manifest tweak: True
# OK: jar пересобран корректно, лишнего не тронуто
```

Скрипт сверяет список записей с оригиналом, ругается на любые неожиданно
изменённые файлы, проверяет что все оставшиеся в `mixins.impact.json` миксины
реально есть в jar, и что логирование выключено.

## Установка

1. Сделайте бэкап рабочей установки клиента.
2. Замените jar в папке, куда его положил инсталлер клиента, на `dist/1.12.2.jar`
   (имя файла можно оставить прежним, чтобы профиль запуска не сломался;
   если хочется нейтрального имени — переименуйте и профиль в лаунчере).
3. Название профиля/папки версии в лаунчере — это не содержимое jar; чтобы и там
   не было названия клиента, профиль нужно переименовать средствами лаунчера.

## Что НЕ реализовано и почему

Запрос был шире рескина; ниже честный статус по каждому пункту.

1. **Бинд «паника»: мод исчезает, все функции выключаются.** На этом jar сделать
   нельзя. Impact 4.9.1 — закрытый релиз: классы обфусцированы (`net/impactclient/9r`,
   `0ay`, …), строки зашифрованы и собираются в рантайме из XOR-констант
   (`ldc; i2l; ldc; i2l; lxor; …; invokestatic`), исходников нет. Чтобы повесить
   обработчик клавиши, нужно вставить вызов в байткод обфусцированного класса:
   это правка `Code`-атрибута с пересчётом `StackMapTable`/`LineNumberTable`/
   exception-таблиц. Сделать это можно, но проверить негде: в песочнице нет ни
   Minecraft, ни Forge, ни возможности запустить игру. Отдавать непроверенный
   патченный байткод, который с высокой вероятностью уронит клиент на старте, —
   хуже, чем не отдавать.
2. **«В чате отвечать только Command not found».** Обработчик чат-команд клиента
   тоже внутри обфусцированных классов, а сообщения — зашифрованные строки.
   Без пересборки из исходников это не правится.
3. **Полное отсутствие логов.** В jar есть только свой `log4j2.xml` — он теперь
   выключен. Но в игре логгер берётся из Forge/Minecraft, и записи вида
   «Mixin config …», «Found mod file …» пишет сам Mixin/FML, а не мод. Убрать это
   можно только переименованием пакетов/конфигов миксинов и пересборкой jar.
4. **Смена названия клиента в коде.** Пакет `net/impactclient`, имена
   `mixins.impact.json`, `TweakClass` видны, если jar открыть. Переименование
   теоретически возможно (замена UTF-8 констант + путей + ключей refmap), но это
   уже вмешательство в байткод без возможности проверить — риск получить
   нерабочий клиент.

Итог: всё, что делается на уровне ресурсов и метаданных, сделано и лежит в
`dist/`. Всё, что требует кода (паника, тихий чат, полная зачистка логов и имён),
требует сборки из исходников — для 4.9.1 их публично нет (репозиторий
`ImpactDevelopment/ImpactClient` переехал в issue-трекер), поэтому это отдельная
большая задача: декомпиляция, восстановление проекта под ForgeGradle 1.12.2 и
пересборка.

## Важно

* Патч не запускался в игре (в песочнице нет клиента) — проверяйте на копии
  установки, оригинальный jar сохранён в репозитории.
* jar не подписан, поэтому замена файла ничего не ломает в проверке подписи.
* `dist/*.jar` — те же 4241 записи, что и в оригинале: список файлов не менялся,
  изменены только 12 записей (см. таблицу), всё остальное побайтово идентично.
